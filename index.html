📓 إجابات الأسئلة الـ 6 المكتوبة بخط يدك في الكشكول

حل كل نقطة كتبتها في ورقتك باختصار ووضوح تام

1️⃣ "distinct in SQL لو بعملها محتاج GROUP BY ولا لا؟"

لا تحتاج أبداً!

• القاعدة: لاستخراج القيم الفريدة بدون تكرار نكتب SELECT DISTINCT cust_id FROM orders; بدون GROUP BY نهائياً.
• لا نكتب GROUP BY إلا لو كنا نحسب دالة تجميعية بجانب العمود مثل SUM(price) أو COUNT(*) أو نفلتر المجموعات بـ HAVING.

2️⃣ "Chunk فشخة — إيه هي Groupby(level=0)؟"

تجميع على الـ Index

• عند كتابة chunk.groupby('category')['price'].sum() داخل اللوب، تتحول category إلى Index (المستوى 0)، لذا عند جمع الدفعات نكتب groupby(level=0).sum() أي "اجمع كل الأرقام التي لها نفس الـ Index".
• البديل الأسهل بدون level=0: ضع as_index=False داخل اللوب وفي النهاية اجمع بـ groupby('category', as_index=False)['price'].sum().

3️⃣ "INTERSECT والفرق بينها وبين INNER JOIN؟"

عمودي vs أفقي

• INNER JOIN يربط أعمدة جدولين أفقياً ويكرر الصفوف لو المفتاح مكرر (M × N) ولا يطابق NULL.
• INTERSECT يقارن نتائج استعلامين عمودياً، ويحذف التكرارات تلقائياً، ويعتبر NULL = NULL متطابقين.

4️⃣ "EXCEPT والفرق بينها وبين LEFT JOIN؟"

عملاء التوقف Churn

• EXCEPT يطرح الاستعلام الثاني من الأول عمودياً ويحذف التكرارات.
• LEFT JOIN ... WHERE right.id IS NULL (ويسمى Anti-Join) يسمح بعرض أي أعمدة من الجدول الأول بحرية وغالباً أسرع على المفاتيح المفهرسة.

5️⃣ "NTILE in Window Functions إيه وظيفتها؟"

تقسيم لشرائح متساوية

• NTILE(4) OVER (ORDER BY spend DESC) تقسم العملاء المرتبين إلى 4 شرائح متساوية (كل شريحة 25%) وتأخذ أرقاماً من 1 إلى 4 (الشريحة 1 هي الـ VIP الأعلى إنفاقاً).

6️⃣ "الفرق بين UNBOUNDED PRECEDING و N PRECEDING؟"

تراكمي vs متحرك

• UNBOUNDED PRECEDING يبدأ دائماً من أول صف في المجموعة (للمجموع التراكمي Running Total).
• 2 PRECEDING يأخذ فقط الصفين السابقين + الصف الحالي (للمتوسط المتحرك Moving Average لـ 3 صفوف).

1️⃣ دوال الترتيب مع التعادل [500, 500, 400] + دالة NTILE:
  • ROW_NUMBER() ⬅ (1, 2, 3) لحذف التكرارات (WHERE rn = 1).
  • RANK() ⬅ (1, 1, 3) تقفز عن الرقم 2.
  • DENSE_RANK() ⬅ (1, 1, 2) بدون قفز (الصحيحة دائماً لثاني أو ثالث أعلى سعر).
  • NTILE(4) ⬅ تقسم العملاء إلى 4 شرائح متساوية (Quartiles 25%).
2️⃣ إطارات النوافذ (ROWS BETWEEN vs RANGE):
  • ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW: للمجموع التراكمي من أول صف.
  • ROWS BETWEEN 2 PRECEDING AND CURRENT ROW: للمتوسط المتحرك لآخر 3 صفوف.
  • نكتب دائماً ROWS BETWEEN صراحةً لأن RANGE الافتراضية تدمج التواريخ المتعادلة!
3️⃣ عمليات المجموعات وفخاخ الـ Joins:
  • UNION ALL أسرع لأنه لا يفحص التكرار؛ INTERSECT للمشترك؛ EXCEPT للمتوقفين (Churn).
  • فخ Fan-out: لا تدمج جدولين بعلاقة 1-to-Many قبل تجميع الجدول الفرعي في CTE أولاً!
🧭 الـ Format الثابت ذو الـ 3 طبقات CTE (امشِ عليه في كل سؤال SQL):
-- خطوة 1: حدد وحدة الصف (Grain) + اجمع الجداول الفرعية لمنع المضاعفة
WITH clean_base AS (
    SELECT cust_id, category, order_date, COALESCE(price, 0) AS price
    FROM orders
    WHERE order_date >= '2026-01-01' AND order_date < '2027-01-01'
),
-- خطوة 2: حسابات النوافذ (DENSE_RANK / LAG / SUM OVER)
enriched_data AS (
    SELECT cust_id, category, price,
           DENSE_RANK() OVER (PARTITION BY category ORDER BY price DESC) AS rnk
    FROM clean_base
)
-- خطوة 3: الفلترة النهائية والترتيب
SELECT cust_id, category, price
FROM enriched_data
WHERE rnk <= 3;
